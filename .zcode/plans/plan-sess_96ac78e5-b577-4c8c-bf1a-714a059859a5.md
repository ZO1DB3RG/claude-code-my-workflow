# 将 claude-code-my-workflow 迁移/调优为 ZCode 版本

## 决策结论（基于调研已定）
- **目标位置**: 当前空目录 `Research_helper/` 作为工作区根（workspace scope），版本化分享
- **领域**: 保留计量经济学 + Beamer/Quarto/R 工具链不动，**只改造运行时层**
- **fan-out**: 用 ZCode `Agent` 工具重写（已验证支持并行 + fresh context）
- **fork**: 已完成 → `ZO1DB3RG/claude-code-my-workflow`（本计划会先克隆进工作区，建立 upstream 跟踪）

## 关键迁移事实（调研验证，决定改造范围）

| Claude Code 机制 | ZCode 实况 | 处理方式 |
|---|---|---|
| `.zcode/` + `AGENTS.md` | `.zcode/` + `AGENTS.md`（workspace scope） | **重命名 + 目录迁移** |
| `.zcode/settings.json` | `.zcode/config.json`（**无** `permissions` 块） | **重写**：权限→按技能 `allowed-tools`；hooks→`hooks.events.*` 且 `enabled:true` |
| SKILL.md 的 `model:`/`effort:` | **两字段在 skill 上均无效**（仅 agent/command 支持 `model`，无 `effort`） | **删除 skill 的 model/effort**；`effort` 概念在 GLM 单模型环境下**整体废弃** |
| agent `.md`（`model:opus/sonnet/haiku`） | 字段被识别，但**本机所有调用都解析为 GLM-5.2**（alias 被 config 覆盖） | **保留 frontmatter 兼容性**，但接受"模型分层失效"现实——改用 agent persona/系统提示区分轻重 |
| `Task(context:fork)` 并行 | ZCode `Agent` 工具：**并行 + fresh context 原生支持**（已被本机日志证明） | **直接等价迁移**，把 `Task/subagent_type=xxx` 改成 `Agent` 工具调用 |
| 自定义 `subagent_type`（如 editor） | 仅 `general-purpose`/`Explore` 内置；**自定义需打包成 plugin** 的 `agents/` 目录 | **打包为本地 plugin**（或退而求其次用 general-purpose + 在 prompt 里注入 agent persona） |
| hooks 事件 `Notification`/`PreCompact`/`SubagentStop` | **不支持**（仅 7 个事件） | **删除** 3 个不支持事件的 hook |
| `$CLAUDE_PROJECT_DIR` | `$ZCODE_PROJECT_DIR`（CLAUDE_ 名仍兼容） | **统一改 ZCODE_** |
| `statusline.sh` 读 `permission_mode` | ZCode 无 permission_mode | **简化或移除** statusline |

## 执行计划（分 7 阶段）

### 阶段 0：地基搭建（克隆 fork 进工作区 + upstream 跟踪）
1. 在 `Research_helper/` 克隆你的 fork：`git clone https://github.com/ZO1DB3RG/claude-code-my-workflow.git .`
2. 添加 upstream 跟踪，便于日后同步原作者更新：
   `git remote add upstream https://github.com/pedrohcgs/claude-code-my-workflow.git`
3. 创建适配分支 `adapt/zcode`（不直接污染 main）

### 阶段 1：目录与入口文件迁移（机械重命名）
- `.zcode/` → `.zcode/`
- `AGENTS.md` → `AGENTS.md`（内容保留，后续阶段微调）
- `.gitignore` 里的 `.zcode/state/` → `.zcode/state/`
- 保留 `quality_reports/`、`scripts/`、`Slides/`、`Quarto/`、`templates/` 等业务目录**原样不动**

### 阶段 2：settings → config 迁移（**最大改动**）
把 `.zcode/settings.json` 重写为 `.zcode/config.json`：
- **删除** `permissions` 块（defaultMode/allow/deny 无对应物）。ZCode 的许可靠交互式 prompt + `PermissionRequest` hook；如需宽松默认，写一个 `PermissionRequest` hook 返回 `allow`
- **hooks 重构**：外层包 `{"hooks":{"enabled":true,"events":{...}}}`
  - 删除 `Notification`（notify.sh）、`PreCompact`（pre-compact.py）、`SessionStart(matcher:compact|resume)` 的 post-compact-restore.py 这三个不支持的
  - `PreToolUse`（git-guardrails.py）、`PostToolUse`（context-monitor.py / claim-reconcile.py）、`Stop`（log-reminder.py）保留，matcher 里去掉 `MultiEdit`（非 ZCode 工具），`Task`↔`Agent` 已自动别名
  - 所有 `command` 里的 `$CLAUDE_PROJECT_DIR` → `$ZCODE_PROJECT_DIR`
- **statusline**：ZCode 的 statusline 机制需核对（计划中先保留脚本但简化，去掉 permission_mode 解析）
- **plansDirectory** 字段：ZCode 是否支持需验证，不支持则由 AGENTS.md 文字约定 `quality_reports/plans/`

### 阶段 3：Skills 批量清洗（52 个 SKILL.md）
- **删除** 每个 SKILL.md frontmatter 的 `model:` 和 `effort:` 行（无效字段，可能触发解析告警）
- 保留 `name`、`description`（确保 <1024 字符）、`allowed-tools`、`argument-hint`
- 全局文本替换引用路径：`.zcode/` → `.zcode/`、`AGENTS.md` → `AGENTS.md`（出现在大量 skill 正文 cross-reference 里）
- `Task` 子 agent 调用语义改写：skill 正文里描述 fan-out 的部分（"spawn N Task calls, context: fork"）改写为 ZCode `Agent` 工具等价表述
- **保留**：所有学术领域逻辑（Beamer 编译、R 审稿、TikZ、DiD、simulation 等技能内容**一字不改**）

### 阶段 4：Agents 批量清洗（18 个 agent .md）
- frontmatter 的 `model: opus/sonnet/haiku` **保留**（字段被识别，保持 Claude 兼容性与未来可迁移性），但接受 GLM 单模型现实
- **删除** `effort:` 行（ZCode 不支持）
- **核心策略调整**：既然模型分层失效，改用**系统提示强度**区分 agent——在 agent 正文里显式强化 persona（"你是高判断层 referee，需谨慎核实"等）。把 `.zcode/rules/model-routing.md` 改写为"persona-routing"说明，说明在单模型环境下用 prompt/persona 替代 model tier
- `.zcode/references/model-versions.md` 重写为 GLM-5.2 为唯一模型的说明，或标注"原 Opus/Sonnet/Haiku tier 概念在 GLM 环境下以 persona 体现"

### 阶段 5：fan-out 运行时重写（**orchestrator 核心改造**）
这是最关键的语义改造。原 `orchestrator-protocol.md` / `orchestration-schemas.md` / 各 fan-out skill 的调用方式从 `Task(subagent_type=X, context:fork)` 改为 ZCode `Agent`：
- **自定义 agent 注册**：由于 ZCode 自定义 subagent_type 需 plugin，有两条路：
  - **方案 A（推荐）**：打包成本地 plugin（`.zcode-plugin/plugin.json`，`agents` 字段指向 `.zcode/agents/`），这样 18 个 agent 能被 `subagent_type=editor` 等调用
  - **方案 B（轻量）**：用 `subagent_type=general-purpose`，在 Agent 的 `prompt` 里注入对应 agent 的完整系统提示（persona 注入），不注册自定义类型
  - 计划中**先走方案 B 跑通**，验证可行后再决定是否升级到方案 A
- 重写 `.zcode/rules/orchestrator-protocol.md` 的"runtime primitives"段：`Task → Agent`、`context:fork → 默认行为`、`subagent_type` 注册机制说明
- **保留**：FINDING/SCORECARD 数据契约、门控谓词（CRITICAL>0→BLOCK）、幻觉门、loop-until-dry——这些是**纯文本协议**，与工具无关，原样保留
- 修订各 fan-out skill（seven-pass-review、review-paper --peer、qa-quarto、deep-audit、slide-excellence）里的 spawn 指令为 ZCode Agent 语法

### 阶段 6：质量门与脚本修复
- `.zcode/scripts/check-surface-sync.py`：它统计 `.zcode/{skills,agents,rules,hooks}` 计数与文档对齐——改扫描 `.zcode/`
- `.zcode/scripts/check-skill-integrity.py`：检查 frontmatter 字段，移除对 `model`/`effort` 的断言（或改为警告）
- `.zcode/scripts/check-model-versions.sh`：原检查 Claude 模型版本陈旧——**改写**为检查 GLM 模型或降级为 no-op
- `scripts/quality_score.py`、`install-hooks.sh`、`validate-setup.sh`：核对工具检查项（XeLaTeX/Quarto/R/gh 仍在），移除/适配 Claude 特有检查
- `.githooks/pre-commit`：检查引用路径

### 阶段 7：验证与首跑
- 运行 `python3 .zcode/scripts/check-skill-integrity.py` 确认所有 skill 可加载、frontmatter 干净
- 起一个最小 fan-out 实验：用 `/seven-pass-review` 或简化版对一个样例 `.tex` 跑，确认 ZCode Agent 并行 fan-out → reduce → judge 全链路通
- 跑 `/commit` 的质量门（quality_score + surface-sync）确认门控生效
- 把 `MEMORY.md` 加一条 `[LEARN:zcode-migration]` 记录迁移要点
- 在 `adapt/zcode` 分支提交，开 PR 合回 main

## 工作量与风险提示

- **工作量**：约 100+ 文件，但大部分是**机械批量替换**（路径、frontmatter 字段）；真正需要语义重写的是**阶段 5 的 orchestrator + 5 个 fan-out skill**，这是脑力密集区
- **最大风险**：自定义 subagent_type 在 ZCode 需要 plugin 机制。计划先用方案 B（general-purpose + persona 注入）降低风险，跑通后再评估是否值得做 plugin
- **放弃的能力**：模型分层（Opus/Sonnet/Haiku 的成本/质量差异）在 GLM 单模型环境**无法复现**——这是不可调和的环境差异，用 persona 弱化替代。`effort` 轴同理废弃
- **原样保留**：全部学术领域知识（计量、Beamer、R、TikZ、复现协议、质量评分逻辑）、orchestrator 的数据契约与门控逻辑

## 建议的推进节奏
我建议**分阶段提交**，每阶段一个 commit，便于回滚。特别是阶段 5（fan-out 重写）完成后做一次实测再继续，避免大范围改完发现 fan-out 在 ZCode 实际行为不符。
